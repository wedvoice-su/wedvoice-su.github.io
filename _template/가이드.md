# 새 사이트 만드는 법

이 폴더(`_template`)는 새 사이트를 시작할 때 복사하는 기본 틀이에요.
이름이 `_`로 시작하는 폴더는 사이트에 올라가지 않아요.

## 폴더 구조

```
index.html                 첫 화면 (허브): 카테고리 버튼을 누르면 그 카테고리 페이지로
hub.js, hub.css            허브 코드 (카테고리 목록은 hub.js 맨 위)
song/                      결혼식 음악 카테고리
  index.html                 음악 테스트 고르는 화면 (신랑·신부 입장곡, 행진곡, 축가)
  song.js, song.css          음악 테스트 코드
groom/ lovely-bride/ hand-in-hand/ sing-for-you/   입장곡·축가 테스트 페이지 (주소)
big-day/                   결혼식 당일 준비 카테고리 (index.html, day.js 맨 위에 사이트 목록)
for-our-parents/           양가 부모님 입장·화촉점화 안내
shared/                    모든 사이트 공통
  brand.css                  색, 글꼴, 첫 화면, A/B 질문, 결과 카드, 버튼
  common.js                  사이트 목록, 로고·서명, 결과 공개, 이미지 저장, 링크 복사
  img/                       로고, 아이콘, 링크 미리보기 이미지
_template/                 새 사이트 기본 틀 (사이트에 안 올라감)
```

## 순서

1. `_template` 폴더를 복사해서 새 사이트 이름으로 바꿔요.
   - 이름이 곧 주소예요: `wedvoice-su.github.io/새이름/`
   - 영어 소문자와 `-`만 쓰고, 다른 사이트 주소에서 짐작하기 어렵게 지어요. (예: `lovely-bride`, `hand-in-hand`)
2. `index.html`의 TODO: 사이트 이름과 한 줄 설명을 바꿔요.
3. `app.js`의 TODO: 질문, 결과, 문구를 이 사이트 내용으로 바꿔요. 이 사이트만의 스타일은 `app.css`에 넣어요.
4. `shared/common.js` 맨 위 "사이트 목록"에 한 줄 추가해요.
   - 릴스 댓글로 링크를 보낼 사이트면 `reel`에 릴스 주소를 넣어요. 다른 사이트의 버튼이 이 사이트 대신 릴스로 가요.
   - 주소를 공개하는 사이트면 `direct: true`를 넣어요. 결과 화면에 "테스트 링크 복사하기"가 보이고, `reel`이 없으면 버튼이 사이트로 바로 가요.
5. 새 카테고리의 첫 사이트면 카테고리 페이지도 만들어요.
   - 카테고리 폴더(예: `song/`)에 `index.html`을 만들어 그 카테고리 사이트들을 고르는 화면으로 써요.
   - 루트 `hub.js` 맨 위 "카테고리 목록"에 한 줄 추가하면 허브에 버튼이 생겨요.
6. 기능이 잘 되는지 시험해요. (당연히 하는 일)
7. **시험이 끝나면, UI·UX 전문가 눈으로 한 번 더 검토하고 고쳐요.** (사회자님 2026-11-13: 모든 사이트에 꼭)
   - 폰 크기 화면을 하나씩 캡처해서, 처음 보는 사람이 설명 없이 쓸 수 있는지 봐요.
   - 볼 것: 첫 화면에서 할 일이 3초 안에 보이나 · 눌러도 오류만 나는 큰 버튼이 없나 · 고르는 순서와 화면 순서가 같나 · 안내 글이 화면 배치와 맞나 · 걱정되는 일(사진 올리기 등) 바로 옆에 안심 문구가 있나 · 폰 뒤로 가기가 이전 단계로 가나 · 지금 필요 없는 칸은 숨겼나 · 뜻 모를 이름이 없나 · 누르는 칸이 40px쯤 되나 · 중요한 것이 스크롤 맨 아래에 숨지 않았나.
   - 고친 뒤 시험을 다시 돌리고, 릴스 키트가 있으면 화면 녹화와 녹화순서도 다시 맞춰요.
8. 푸시해요.

## 지킬 것

- `shared/` 파일을 고치면 모든 사이트가 바뀌어요. 한 사이트만 바꾸고 싶으면 그 사이트 폴더의 파일을 고쳐요.
- 이미 공유한 사이트의 폴더 이름(주소)은 바꾸지 않아요. 바꾸면 링크를 받은 분들에게 404가 떠요.
- 문구는 모두 사회자님이 직접 확인한 뒤에 올려요.
- **릴스를 이미 올린 사이트는 고치지 않아요.** (사회자님 2026-11-13) 위 7번 UI·UX 검토도 릴스를 올리기 전 사이트에만 해요. 올린 사이트에서 오류를 찾으면 고치지 말고 사회자님께 먼저 알려요. 릴스를 올렸는지는 `shared/common.js` 사이트 목록의 `reel` 칸에 주소가 있는지로 봐요.
